# MTT S30 第四轮候选修复与验证

本轮已完成源码修复及双内核干净重建，下一次受控测试固定使用新模块 `db8e4393ec50e0e2542dafdb7277240627406b847dc19d0427444712249143bb`。尚未加载本轮模块，不能宣布硬件适配完成。上一轮的原始日志和所有旧构建均保留。

## 修复内容

1. **PVR 工作队列**：包括先前遗漏的 `mtgpu-wq` 在内，全部 6 个直接 `alloc_workqueue` 调用均走兼容层；新内核显式使用 PERCPU，旧内核保留原默认。未增改闭源枚举布局。
2. **S30 初始显示关闭超时**：原来 `deinit → stop` 等待 `disable_done`，但逻辑中断尚未开放。仅对 PCI `1ed5:0102`、GEN1，在注册 ISR 之前屏蔽硬件中断、清除旧的关闭完成位、关闭显示，然后轮询硬件原始完成位，最多 500 ms。成功后才继续原厂 deinit；超时和全 1 无效读数返回错误，不伪造 `disable_done`。
3. **VPU 与 DISPC 寄存器重叠**：仅对 S30 原生/host 模式且配置完整匹配时，将 Linux 映射长度从 `0xf000` 修正为 `0xe000`。保留三个 `0x4000` core 区及 TOP `0xd000..0xdfff`，排除 `BAR0+0x116000` 的 DISPC 页。运行时还检查 BAR 长度、实际显示子资源的起点；任一配置变化直接拒绝初始化。没有修改厂商的 `mt_conf` 或关闭资源检查。

显示 IRQ 在 CRTC 构建成功后才注册；DRM 私有尾部字段在 `drm_vblank_init` 完成后以 release/acquire 发布就绪状态。ISR 在未就绪阶段只应答硬件，不访问 CRTC/vblank。退出时撤销就绪状态、同步实际分配的 Linux host IRQ，随后清理 DRM；组件注销前也先关闭逻辑中断并同步物理 IRQ。初始化失败会释放本组件已创建的 plane/CRTC，并清理 drvdata；`devm_ioremap` 的 NULL 检查也已修正。

## 证据与局限

显示控制寄存器 `0x00/bit0`、原始状态 `0x18/bit8`、屏蔽寄存器 `0x1c`，由固定厂商 blob 的 `dispc_stop` / `dispc_isr` / `dispc_deinit` 反汇编确认；公开的 [Renesas DB9000 驱动提交](https://lkml.indiana.edu/hypermail/linux/kernel/2004.3/02743.html) 对这些寄存器定义提供交叉核对，但它面向其他 SoC，不能替代本机验证。

VPU 范围依据第三轮 `/proc/iomem`、固定 blob 的 SUDI 配置、已定位的 TOP 访问。对 `mt_chip.vaddr` 直接字段引用的扫描不是所有动态访问的完整证明；视频接口、实际解码和持续运行仍须在真机验证。新增的映射约束会在已知配置变化时停止，不能证明闭源代码永不越界。

IRQ 数量及 `host_irq` 字段与厂商 `mtgpu_interrupt_init` 分配/填充路径核对；没有把设备逻辑编号 58 当作 Linux IRQ 使用。对 8 个相关结构比较旧/新模块 DWARF：所有旧字段的偏移和大小不变。只给开源拥有的结构添加尾部字段，`mtgpu_dispc_ctx`、`mt_chip`、`mt_conf` 等结构不变。这个检查不等于全部闭源 ABI 已形式化验证。
