# v10 KWin startup warnings

The successful 20261109-153310 session retains two failed swrast loads, one eglInitialize failure with EGL_NOT_INITIALIZED, and a PipeWire connection failure. These should remain visible in the record. They already appear at the same positions in the v8 and v9 logs.

KWin source from the reviewed 6.8.2 build contains an optional software-device probe during GpuManager construction. In src/core/gpumanager.cpp, lines 79–96, opening /dev/udmabuf leads to RenderDevice::createSoftwareDevice before scanForRenderDevices. A NULL result simply skips adding that optional device. The software-device implementation in src/core/renderdevice.cpp, lines 371–393, enumerates EGL devices, finds EGL_MESA_device_software, then creates an EGL_PLATFORM_DEVICE_EXT display. The exact eglInitialize messages are emitted by src/opengl/egldisplay.cpp, lines 61–68, on a failed initialization. The generic GBM device path also calls EglDisplay::create at renderdevice.cpp:364, so the shared message alone cannot uniquely identify the attempted display.

The optional software-device probe is the likely origin of the swrast failure sequence. KWin's test environment restricts LIBGL_DRIVERS_PATH to the original vendor DRI directory, whose software modules are named swrast_musa_dri.so and kms_swrast_musa_dri.so. The log names swrast and then proceeds into successful S30 initialization and format handling. Current /dev/udmabuf exists; the test runs as root. KWIN_DISABLE_UDMABUF_IMPORT controls the import path in egldisplay.cpp and does not guard the GpuManager constructor's probe. Exact per-display runtime attribution remains an inference because this run did not trace eglInitialize's arguments or stack.

For PipeWire, the source attribution is direct. ScreencastManager construction calls getPipewireConnection at src/plugins/screencast/screencastmanager.cpp:35, before any screen-cast request is needed. getPipewireConnection at lines 195–205 invokes PipeWireCore::init and allows an invalid connection object to be returned when initialization fails. pipewirecore.cpp:83–87 logs the observed message when pw_context_connect returns NULL. The test uses a newly created root-only desktop-runtime directory as XDG_RUNTIME_DIR and starts an isolated D-Bus session. It does not start a PipeWire server there. That isolation is consistent with the observed connection failure. A socket trace was not captured, so the specific errno was not measured. Screen capture through PipeWire has not passed a test.

The measured physical session remains valid within its stated scope. Before and after the client, KWin reported DRM, the enabled 1920×1080 HDMI-A-1 output, OpenGL ES, MOORE THREADS and MTT S30. The recorded output swapchain selected XR24 with importMode 0 and bufferTarget 0. The native S30 client passed all 60 frames and presentation feedback with exit 0, and KWin stayed alive after client cleanup before controlled SIGTERM. The successful S30 context and output path coexist with the earlier optional EGL probe failure.

Report this as successful isolated hardware rendering, native client cleanup and recovery. Describe the residual software-device initialization warning and unavailable PipeWire path as open scope. Do not claim the entire KWin startup is warning-free or all desktop functions are verified.
